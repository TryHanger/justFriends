# Архитектура backend проекта

## Назначение

Backend принимает поэтический текст или документ, извлекает текст, вызывает NLP-модуль,
сохраняет исходный текст и результат, затем возвращает фронтенду единый JSON.
Режим `NLP_BACKEND`: `openai`, `ollama`, `baseline`, `xlmr` или `hybrid`.
Подробности модуля Арслана — в `docs/NLP.md`, контракт — в `docs/NLP_CONTRACT.md`.

## Слои приложения

```text
Клиент Никиты
      │ HTTP / JSON / multipart
      ▼
FastAPI: app/api/v1/routes
      ├── health.py       проверка сервиса и БД
      └── analyses.py     анализ, загрузка, получение результата
               │
               ├── document_loader.py  TXT / PDF / DOCX → исходный текст
               ├── analyzer.py         app/nlp → AnalysisResult
               └── SQLAlchemy          AnalysisRecord → база данных
```

## Поток анализа

1. Клиент отправляет текст или загружает файл.
2. API проверяет язык и размер входа. Для файла парсер извлекает текст.
3. Analyzer передаёт неизменённый исходный текст выбранному NLP-детектору. Для LLM требуется ответ по JSON Schema; для XLM-R используется локальный checkpoint.
4. Pydantic проверяет формат, а backend проверяет, что каждый диапазон `text[start:end]` совпадает с фрагментом модели.
5. Backend сохраняет текст, имя исходного файла, версию модели и результат.
6. API возвращает `analysis_id` и обнаруженные фрагменты.

## Контракт анализа

`POST /api/v1/analyze`

```json
{
  "text": "Poem text in Chinese or Kazakh",
  "language": "auto"
}
```

`language`: `auto`, `zh` или `kk`.

Успешный ответ содержит:

```json
{
  "analysis_id": 1,
  "language": "kk",
  "model_version": "configured GPT model",
  "metaphors": [
    {
      "text": "source span",
      "start": 0,
      "end": 11,
      "label": "metaphor",
      "source_domain": "nature",
      "target_domain": "emotion",
      "confidence": 0.86,
      "rationale": "Short context-based explanation"
    }
  ]
}
```

Смещения нулевые, `end` не включается. Они считаются по Python-символам в извлечённом исходном тексте. Frontend должен использовать те же символы и переносы строк, возвращённые системой.

`POST /api/v1/analyze/file` принимает multipart-поля `file` и `language`. В текущем каркасе поддерживаются UTF-8 TXT, текстовые PDF и DOCX. Сканированные PDF возвращают понятную ошибку до подключения OCR; поддержка DOC, ODT и RTF относится к следующему этапу.

`GET /api/v1/analyses/{analysis_id}` возвращает сохранённый результат. `GET /api/v1/health` возвращает статус API и БД.

## Границы модулей команды

- **Арман:** FastAPI, конфигурация, загрузка и извлечение документов, БД, хранение результатов, API и интеграция.
- **Арслан:** корпус, инструкция разметки, gold-набор, XLM-R, категории и межъязыковые embeddings.
- **Никита:** интерфейс, визуализация, сценарии тестирования, документация и презентация.

Для подмены GPT или добавления XLM-R сохраняйте публичную функцию `analyze_text(text, language) -> AnalysisResult`. Следующий шаг интеграции: адаптер Арслана должен вернуть этот контракт либо отдельный результат, который `analyzer.py` объединит перед сохранением.

## Хранение

`analyses` хранит язык, версию модели, имя файла, извлечённый исходный текст, JSON-результат и время создания. SQLite используется локально. Для общего окружения задайте PostgreSQL через `DATABASE_URL`. Ключ GPT хранится только в переменной `OPENAI_API_KEY` и не записывается в базу или репозиторий.

## Обработка ошибок

| Ситуация | HTTP | Поведение |
|---|---:|---|
| Неподдерживаемый формат | 415 | API сообщает поддерживаемые форматы |
| Файл больше лимита | 413 | обработка прекращается до парсинга |
| Повреждённый документ или пустой текст | 422 | пользователь получает безопасное сообщение |
| Сканированный PDF без текстового слоя | 422 | указывается, что OCR ещё не подключён |
| Нет `OPENAI_API_KEY` | 503 | health/docs доступны, анализ отключён |
| Некорректный ответ провайдера | 502 | сырой ответ или секреты не раскрываются |
| Неизвестный `analysis_id` | 404 | сообщается, что анализа нет |

## Последовательность ближайших интеграций

1. Согласовать реализованную таксономию версии 1.0 из `contracts/taxonomy.json`.
2. Собрать gold-корпус, обучить XLM-R и настроить подключённый адаптер `NLP_BACKEND`.
3. Передать Никите URL и JSON-примеры из `/openapi.json`.
4. Следующей документной зависимостью добавить OCR для сканированных PDF и конвертацию DOC/ODT/RTF.
