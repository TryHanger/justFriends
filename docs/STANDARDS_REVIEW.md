# Ревью и проверка стандартов

Проверено 5 октября 2026 года. Основа адаптации — лабораторные работы №1–2 (каталог,
поиск, группировка), №3–4 (граф процессов и готовность) и №5–6 (ISO/IEC 25010:2023,
верификация и валидация). Лабораторная №9–10 посвящена Agile и UML и требует
отдельного моделирования; панель стандартов не заявляет её выполнение.

## Найдено и исправлено

| Проблема | Риск | Исправление |
|---|---|---|
| `GET /standards/lifecycle` возвращал заранее заданные `completed` и `Conditionally Ready` | UI выдавал вымышленную готовность | Состояние выводится из существующих артефактов; пользовательская валидация и эксплуатация остаются без свидетельств и блокируют готовность |
| `POST /standards/quality/run` подменял недоступный результат числами 10/10 либо 5/10, а время тестов превращал в произвольный балл | Ложная оценка качества | Подсчёт по JUnit XML от реального запуска `pytest`; сбой сбора и таймаут дают `INCOMPLETE` |
| Три характеристики качества объявлялись проверенными только по запуску unit-тестов | Неверная интерпретация ISO/IEC 25010 | Все девять характеристик показаны с критерием и методом. Непроверенные имеют статус `not_evaluated` |
| Каталог не имел выпусков, ссылок и связи с проектом | Невозможно проверить актуальность и применимость | Указаны выпуск, назначение, источник и артефакты; устаревший IEEE 829 помечен историческим |
| Интерфейс скрывал большинство полей каталога и не показывал отдельные тесты | Нельзя проверить выводы | Поиск, фильтр, распределения, свидетельства и результаты тестов доступны в UI |
| Отсутствие `pypdf` ломало импорт всех маршрутов анализа, включая TXT | Недоступность API из-за одного необязательного формата | PDF-зависимость загружается при обработке PDF; при отсутствии возвращается 503 |
| Тест адаптера LLM проверял параметры второго вызова как параметры первого | Ложный сбой теста | Первый и второй вызовы проверяются раздельно; неоднозначное исправление смещения тестируется с действительно неверным смещением |

## Как воспроизвести

```powershell
python -m pytest -q
cd frontend
npx tsc -b --pretty false
node node_modules/vite/bin/vite.js build --configLoader native
```

Панель «Качество и тесты» вызывает локальный API и запускает фиксированный набор
тестовых файлов с ограничением 90 секунд. Запуск разрешён только при
`ENVIRONMENT=local`. Docker Compose публикует только сайт на loopback адресе хоста, а API доступен через прокси Nginx. Никакая команда пользователя
в endpoint не передаётся. `INCOMPLETE` означает отсутствие полного набора данных,
например пропущенный тест; `PASS` означает только успешный исход выбранных тестов.

Профиль качества — учебная адаптация ISO/IEC 25010:2023, а не заявление о
сертификации. Доля пройденных тестов и выбранные пороги являются метриками
проекта, не формулами стандарта. Нагрузочных испытаний, оценки безопасности,
кроссбраузерной проверки и пользовательской валидации пока нет. Поэтому
эксплуатационная готовность не подтверждена.

## Источники выпусков

- [ISO/IEC 25010:2023](https://www.iso.org/standard/78176.html) — модель из девяти характеристик.
- [ISO/IEC/IEEE 12207:2017](https://www.iso.org/standard/63712.html) — процессы жизненного цикла ПО.
- [ISO/IEC/IEEE 29148:2018](https://www.iso.org/standard/72089.html) — инженерия требований.
- [ISO/IEC/IEEE 42010:2022](https://www.iso.org/standard/74393.html) — описание архитектуры.
- [IEC 62443-4-1:2018](https://webstore.iec.ch/en/publication/33615) — отдельный пример стандарта IEC для промышленной автоматизации, не прямое требование к этому проекту.

и национальные записи служат сравнительному анализу; их присутствие не означает
обязательность или соответствие требованиям конкретной юрисдикции.
