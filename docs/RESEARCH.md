# Исследовательский план Арслана

## Цель

Оценить, насколько автоматические методы обнаруживают метафорические выражения
в китайской и казахской поэзии и помогают находить семантически сопоставимые пары.
Разделить качество обнаружения границ, классификации областей и межъязыкового поиска.

## Проверяемые гипотезы

1. Дообученный XLM-R превосходит словарный baseline по exact-span F1 на каждом языке.
2. Дополнение XLM-R предварительным анализом LLM повышает Recall либо снижает
   число ошибок областей; возможное падение Precision нужно измерить отдельно.
3. Embeddings повышают Recall@k релевантных межъязыковых пар относительно случайного
   ранжирования на фиксированном пуле кандидатов.

Это гипотезы, а не установленные результаты. Не выбирать модель по тесту.
Порог, состав словаря и prompt фиксировать после экспериментов на validation.
Численные целевые значения качества команда определяет после пилота;
произвольные обещания F1 до появления корпуса не обоснованы.

## Корпус и источники для проверки

| Язык | Найденный источник | Статус |
|---|---|---|
| Китайский | [chinese-poetry](https://github.com/chinese-poetry/chinese-poetry) | Репозиторий указывает MIT; сохранить точную ревизию, лицензию и путь исходного файла |
| Казахский | [Категория стихотворений Абая в Wikisource](https://wikisource.org/wiki/Category:Абай_Құнанбайұлының_өлеңдері) | Кандидат; проверить страницу каждого текста, редакцию и условия использования |

Полный корпус в репозиторий пока не добавлен. Эти ссылки являются реестром кандидатов,
не подтверждением готового датасета. Для каждого текста нужны `source_url`, `license`,
`license_verified`, автор, эпоха, язык и общий `work_id` оригинального произведения.
Проверять права конкретного издания/перевода и сохранять требуемую атрибуцию.
Современную редакцию нельзя считать свободной только из-за возраста оригинала.

Сохранять традиционную/упрощённую китайскую графику и казахские буквы; не выполнять
автоматическую транслитерацию. Переводы и оригиналы не подменяют друг друга.
До разметки удалить дубликаты и отдельно разобрать близкие варианты. Текущий
детектор дубликатов учитывает Unicode NFC и пробельные отличия, но не находит
парафразы или все варианты орфографии — их проверяет человек.

## Дизайн эксперимента

- Составить сопоставимые подкорпуса по объёму, эпохам и жанрам. Не смешивать
  различия состава выборок с межкультурными различиями.
- Разделить по произведению; для более строгого опыта дополнительно разделить
  по авторам вручную. Автоматический `split` группирует по `work_id`, не по автору.
- Сохранить test до экспериментов. Для каждого запуска записать модель, версию
  таксономии, prompt, seed, хеши данных, параметры и окружение.
- Сравнить baseline, LLM zero-shot, XLM-R и hybrid на одних документах и определении
  положительной метки. Учитывать пустые предсказания и ошибки провайдера отдельно.
- Отдельно отчёт по `zh` и `kk`, количеству примеров каждого класса и авторам.
  Для итогового отчёта рассчитать интервалы неопределённости ресэмплированием
  произведений, а не отдельных токенов.
- Для retrieval независимо разметить пары носителями языков, зафиксировать кандидатов
  и считать Recall@1/5/10 отдельно в обоих направлениях. Cosine не равен вероятности.
- Межкультурные выводы строить по проверенным контекстам и частотам с указанным
  знаменателем. Не приписывать национальные черты авторам или читателям.

## Методические и технические источники

- [MIPVU](https://www.vismet.org/metcor/documentation/MIPVU.html) — сопоставление базового и контекстного смысла; наша разметка выражений является адаптацией.
- [Metaphor Detection in a Poetry Corpus](https://aclanthology.org/W17-2201/) — исследование поиска метафор в поэзии; результаты другой задачи не переносить на наш корпус.
- [Hugging Face token classification](https://huggingface.co/docs/transformers/main/en/tasks/token_classification) — токенная классификация.
- [Tokenizer offsets](https://huggingface.co/docs/tokenizers/api/encoding) — сопоставление токенов и исходного текста.
- [Multilingual E5](https://huggingface.co/intfloat/multilingual-e5-base) — префиксы, ограничения и применение embeddings.
- [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) — ограничение формата ответа, которое не гарантирует истинность содержания.
- [Ollama chat API](https://docs.ollama.com/api/chat) — локальный LLM и JSON Schema в `format`.
- [Label Studio export](https://labelstud.io/guide/export.html) — исходный формат аннотаций и предсказаний.
