# Отчёт о реализации проекта «Анализатор метафор»

**Дата проверки:** 13 октября 2026 года  
**Основа отчёта:** локальная версия проекта, коммит `d353ce6`.

**Обновление:** добавлен интерактивный центр проверок и отдельная панель проектных измерений по ISO/IEC 25023:2016. Актуальное описание и сценарий демонстрации находятся в `docs/CHECKS_CENTER.md`. На 13 октября 2026 года после расширения тестов локально прошли 65 серверных тестов, 1 необязательный тест XLM-R пропущен. Фронтенд: 38 тестов прошли. Эти результаты относятся к рабочему дереву с незакоммиченными изменениями, а не к коммиту `d353ce6`.

## 1. Цель работы

Разработать веб-приложение для анализа метафор в китайских и казахских текстах, сохранения результатов и их сравнения. Дополнительно представить преподавателю учебную адаптацию заданий по стандартам: каталог источников, модель жизненного цикла и проверяемые свидетельства качества проекта.

## 2. Состав системы

| Компонент | Реализация | Назначение |
| --- | --- | --- |
| Сервер | Python, FastAPI, SQLAlchemy | Приём и обработка запросов, сохранение анализов, экспорт и сравнение |
| Веб-интерфейс | React, TypeScript, Vite | Загрузка текстов, просмотр результатов, библиотека, сравнение и панель стандартов |
| Хранилище | PostgreSQL в Docker Compose; SQLite для локальной разработки | Сохранение анализов и библиотеки |
| Развёртывание | Docker Compose, Nginx | Запуск сайта на `http://localhost:8080`; маршрутизация запросов к API |
| Проверки | pytest, Vitest, Ruff, проверка типов и сборка; GitHub Actions | Регрессионные проверки сервера и интерфейса |

Сервис содержит страницы главной панели, результата анализа, сравнения, библиотеки и стандартов. Интерфейс поддерживает русский и английский языки.

## 3. Реализованные функции

1. **Анализ текста.** Пользователь отправляет текст или файл; API создаёт задачу, возвращает идентификатор, а интерфейс показывает её состояние и результат. Доступны TXT в UTF-8, PDF с текстовым слоем и DOCX. Для найденных метафор передаются фрагмент исходного текста, символьные позиции, метка, домены источника и цели, уверенность, пояснение и версия модели.
2. **История и экспорт.** Результаты сохраняются в базе данных; есть список анализов и выгрузка отдельного результата в JSON или CSV.
3. **Сравнение.** Реализованы агрегированное сравнение результатов для двух языков и отдельное ранжирование семантически близких кандидатов.
4. **Библиотека.** Можно добавлять документы и просматривать записи с метаданными; анализ связывается с записью библиотеки.
5. **NLP-модуль.** Есть автономный словарный режим для демонстрации, адаптеры OpenAI и Ollama, подготовка корпуса и аннотаций, код обучения и применения XLM-R, гибридный детектор и средства семантического сравнения. По умолчанию Docker запускает автономный режим. Нейросетевые варианты требуют отдельных зависимостей, настроек и, для XLM-R, обученной модели.
6. **Ограничения входных данных.** Проверяются размер загрузки и длина извлечённого текста; по умолчанию пределы составляют 20 МиБ и 100 000 символов.

## 4. Адаптация лабораторных работ и стандарты

| Материал | Что представлено в проекте | Где посмотреть |
| --- | --- | --- |
| Лабораторные № 1–2: каталог, поиск, группировка | Каталог 12 стандартов с обозначением, выпуском, областью применения, назначением, примером, ссылкой на источник и связью с артефактами проекта. Есть поиск, фильтр и распределения. | Страница `/standards`, раздел каталога |
| Лабораторные № 3–4: жизненный цикл | Модель из девяти процессов с входами, выходами, ответственными, зависимостями и свидетельствами. Готовность вычисляется по наличию артефактов и критическим пробелам. | Страница `/standards`, раздел жизненного цикла |
| Лабораторные № 5–6: качество | Панель показывает девять характеристик ISO/IEC 25010:2023 и четыре проектных измерения по подходу ISO/IEC 25023:2016 с формулами, датой, источником и пределами вывода. Центр проверок сохраняет реальные запуски pytest, Ruff и проверок интерфейса; доступны история, детали и сравнение. | Страница `/standards`, разделы качества и «Проверки проекта» |
| Лабораторные № 9–10: Agile и UML | Отдельная модель по этим заданиям пока не реализована. | — |

В каталоге, в частности, представлены ISO/IEC/IEEE 12207:2017, ISO/IEC 25010:2023, ISO/IEC/IEEE 29148:2018 и ISO/IEC/IEEE 42010:2022. Ссылки на первоисточники и применимость каждой записи доступны в интерфейсе. Исторический IEEE 829-2008 помечен как исторический.

Панель жизненного цикла показывает наличие файлов-свидетельств, а не подтверждение выполнения всех процедур. Валидация с пользователями и эксплуатация пока не имеют достаточных свидетельств. Панель качества не выдаёт сертификат ISO: большинство характеристик остаются без отдельной оценки. Центр проверок включается только в локальном режиме и не требует ввода токена. В Docker API доступны pytest и Ruff; отдельный закрытый контейнер выполняет Vitest, проверку TypeScript и сборку интерфейса.

## 5. Проверка реализации

На локальной версии 13 октября 2026 года выполнен запуск `python -m pytest -q -rs`: **65 тестов прошли, 1 пропущен**. Пропущен необязательный тест XLM-R, поскольку пакет `transformers` не установлен в текущем окружении. Дополнительно 38 тестов интерфейса прошли. Проверки охватывают API, контракты данных и реализованную серверную логику; такой результат подтверждает прохождение этих тестов, но не качество обученной модели и не соответствие всем требованиям ISO.

В репозитории также настроен конвейер GitHub Actions для Python 3.11/3.12, статической проверки Python, серверных тестов, проверок и сборки фронтенда. Наличие конфигурации не является свидетельством успешного удалённого запуска. После пересборки Docker через API выполнены реальные проверки: pytest — 65 passed и 1 skipped из-за необязательной зависимости `transformers`; Ruff — passed; Vitest — 38 passed; TypeScript — passed; сборка Vite — passed в предыдущем запуске Docker. Панель ISO/IEC 25023:2016 показывает по последним сохранённым запускам 65/65 и 38/38 успешных выполненных тестов, один пропуск серверного теста, 0 замечаний Ruff и 0 ошибок TypeScript. История реальных запусков сохранилась после перезапуска контейнера API. Результаты фиксируют состояние локального рабочего дерева на дату проверки.

## 6. Известные ограничения и дальнейшая работа

- Для сканированных PDF нет распознавания текста; DOC, ODT и RTF не обрабатываются. Длинные документы автоматически не разбиваются на части.
- Задачи анализа выполняются внутри процесса API. Для нескольких экземпляров сервера и надёжного восстановления задач нужна отдельная очередь.
- Для исследовательского вывода необходимы размеченный корпус, независимая экспертная проверка, обучение моделей и измерение качества на отложенных данных. Демонстрационные результаты не подтверждают научные выводы о межкультурных различиях.
- Не выполнены отдельные нагрузочные испытания, аудит безопасности, проверка удобства с пользователями и подтверждение эксплуатационной готовности.
- Лабораторные № 9–10 требуют отдельной работы по Agile и UML.

## 7. Вывод

Реализован работающий учебный прототип с сервером, веб-интерфейсом, хранением и сравнением результатов, Docker-развёртыванием и воспроизводимыми тестами. Страница стандартов позволяет показать преподавателю конкретные источники, связь с проектными артефактами и результаты проверок. Представленные свидетельства отражают выполненную часть работы; полное соответствие стандартам и научная валидность NLP-моделей пока не заявляются.
