Анализатор метафор: что сделано по ТЗ и как это устроено

Программный комплекс выявляет метафоры в китайских и казахских стихах, классифицирует их, подписывает смысл и тональность и сопоставляет образы двух традиций. Этот документ описывает, что реализовано, на чём построено, как работает и что осталось сделать по техническому заданию.

Итог

Подсчёт по 31 пункту ТЗ. «Сделано» — реализовано в коде, покрыто тестами и запускается. «Частично» — инструмент готов, но результат зависит от данных или прогонов, которых ещё нет. «Нет» — требует работы людей: сбора текстов, разметки, публикаций.

Готово

Конвейер модулей A–E, все поля вывода из ТЗ, стратегии промптов (zero-shot, few-shot, CoT, RAG, словарь), адаптеры OpenAI, Claude, Ollama и локальных моделей, метрики раздела 6, инструменты под гипотезы H1–H3, веб-интерфейс и API.

Не хватает данных

Нет собранных корпусов и Golden Test Set от трёх экспертов. Поэтому значения F1 и гипотезы пока не проверены. Словари-ограничения и база RAG стартовые и требуют проверки филологами.

Как работает анализ

Путь одного стихотворения от ввода до результата. Шаги 2–5 — модули A–D из ТЗ; шаг 6 — модуль E.

ВводТекст или файл TXT, PDF, DOCX. API ставит задание в очередь и сразу отвечает 202.
A. ПодготовкаОпределение языка, NFC; при подготовке корпуса — нормализация знаков и очистка помет.
B. КандидатыСловарь-ограничение находит растения, животных, явления, абстракции. Для казахского — со всеми аффиксами.
C–D. LLMПромпт по стратегии: инструкции MIP, примеры, шаги CoT, найденные фрагменты RAG, кандидаты. Ответ строго по JSON-схеме.
ПроверкаPydantic-схема, сверка смещений с исходным текстом, вычисление Context_Sentence, слияние кандидатов.
E. РезультатСохранение в БД, показ в интерфейсе с пометкой «требует проверки», экспорт в формате ТЗ, разметка экспертами.

Что возвращает модель

Для каждой фигуры: фрагмент и его смещения, Entity и её тип, тип фигуры, исходная и целевая области, семантическая метка, тональность, уверенность и обоснование. Отдельно — сущности, употреблённые буквально.

Как защищены результаты

Фрагмент, которого нет в тексте, отбрасывается с предупреждением, а не «угадывается». Язык ответа проверяется. Обоснования не на русском переводятся отдельным коротким запросом. Каждый результат помечен как требующий проверки.

Воспроизводимость

В поле method записаны стратегия, хеш промпта, фактически применённые T и top-p, версия словаря и документы RAG. Раннер экспериментов дополнительно хранит хеши данных.

Что сделано

Формат и таксономия 2.0

  • Поля ТЗ: Entity, Type, Context_Sentence, Usage_Type, Source/Target_Domain, Semantic_Label, Evidence_Reasoning, а также тональность.
  • 10 типов сущностей, 23 области, 5 типов фигур.
  • Старые результаты читаются без миграции.

Модули B–D

  • Словари zh и kk: около 50 записей на язык с традиционными прочтениями.
  • Решение literal/metaphorical для каждой сущности.
  • CoT по MIP: базовое значение → контекстное → контраст.

Методы и модели

  • Стратегии zero-shot, few-shot, CoT, RAG, lexicon в любых сочетаниях.
  • RAG на BM25 по базе MIP/MIPVU и комментариям.
  • OpenAI, Claude, Ollama, локальные Transformers с LoRA.

Метрики и эксперименты

  • F1 по сущностям, бинарной классификации, этикетированию.
  • Fleiss' и Cohen κ, бутстрэп по произведениям.
  • Раннер «метод × модель» со сводкой и флагами целей ТЗ.

Под гипотезы H1–H3

  • H1: генератор IFT-датасета и LoRA-дообучение.
  • H2: фертильность токенизаторов, казахский BPE на 50K.
  • H3: послойные пробы и MDL.

Данные, разметка, интерфейс

  • Импорт chinese-poetry («Чу Цы») и папок с CSV, очистка zh и kk.
  • Label Studio 2.0: сущности, тональность, метки, двухэтапная проверка.
  • UI: сущности, тональность, контекст, метод, экспорт ТЗ.

H1. Дообучение лучше промптинга

Одна модель с zero-shot, few-shot и полным RAG против той же модели после LoRA на IFT-датасете. Сравнение на одном test, интервалы бутстрэпа.

H2. Казахский токенизатор

Фертильность SozKZ против Qwen, LLaMA и XLM-R на казахском корпусе и F1 только по kk, с учётом числа параметров.

H3. Средние слои

Пробы на каждом слое, F1 с GroupKFold по произведениям и сжатие MDL. Гипотеза подтверждается, если пик стабильно в средней трети слоёв.

Раннер experiment сохраняет для каждого запуска предсказания, ошибки провайдера и метрики, а также сводку summary.md с флагами целей ТЗ. Ошибки считаются пустыми предсказаниями, поэтому тест не «сжимается». Готовые запуски не повторяются.

Запуск локально

Из корня репозитория в PowerShell. Бэкенд слушает порт 8000, интерфейс — http://localhost:5173.

1. Окружение и зависимости (один раз) 
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
Для XLM-R, эмбеддингов, пробинга и дообучения 
.\.venv\Scripts\python.exe -m pip install "torch>=2.6,<3" --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -e ".[dev,nlp,finetune]"
2. Бэкенд (для бесплатной проверки поставьте NLP_BACKEND=baseline в .env) 
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
3. Фронтенд, во втором терминале 
npm --prefix frontend install
npm --prefix frontend run dev
Проверки 
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app scripts tests
npm --prefix frontend test

Стоимость запросов

Токены тратят только openai, anthropic и hybrid. Один анализ — обычно один запрос; если модель написала обоснование не по-русски, добавляется короткий запрос на перевод.

Стратегия≈ входных токеновПример для Claude Opus 5.5
zero_shot~1,5 тыс.Дешевле всего
cot+lexicon~2 тыс.Хороший режим для повседневной работы
few_shot+cot+rag+lexicon~3,5–4,5 тыс.≈ $0.03–0.06 за короткое стихотворение

Ответ — примерно 150–300 токенов на каждую найденную фигуру; рассуждения «думающих» моделей тоже оплачиваются. Прогон Golden Set на 500 фрагментов — около $15–30 на одну пару «модель × стратегия». Это оценка, а не замер: подсчёт фактического расхода пока не встроен.

Сверка с ТЗ по пунктам

Что осталось

Почти всё оставшееся — работа с данными и людьми. Код для каждого шага уже есть.

P0 · данные

Корпуса

  1. «Чу Цы» и танская поэзия через import-chinese-poetry.
  2. Казахские эпос, жырау, Абай, современные поэты через import-texts.
  3. Проверить лицензии, выставить license_verified.
  4. clean --verse-lines.
P0 · люди

Golden Set

  1. Пилот разметки по инструкции 2.0.
  2. 300–500 фрагментов, 3 эксперта, слепой первый этап.
  3. agreement a b c, цель κ ≥ 0.75.
  4. Расширить словари и базу RAG со ссылками на издания.
P1 · этап 2

Пилотные прогоны

  1. Заполнить experiments/pilot.example.json.
  2. experiment на test.
  3. Найти идентификатор SozKZ.
  4. Разобрать ошибки.
P2 · этапы 3–4

Гипотезы и публикация

  1. build-ift + finetune на GPU → H1.
  2. fertility, train-tokenizer → H2.
  3. probe по нескольким моделям → H3.
  4. Межкультурный отчёт, датасет, веса, статьи.

Важно знать

  • Цитата Ван И в базе RAG и прочтения в словарях стартовые; до публикации их нужно сверить с изданиями.
  • Метрики сущностей считаются только по записям gold, где размечены candidates.
  • XLM-R оставлен опорной моделью, он не заменяет LLM.
  • Ветка feat/tz-alignment ещё не слита в main.
Требования: tz_llm_metaphors_poetry.docx. Описание соответствует коду ветки feat/tz-alignment; качество моделей на реальной поэзии пока не измерялось.
