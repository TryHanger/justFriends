Итог по пунктам ТЗ

«Сделано» — реализовано в коде, покрыто тестами и запускается. «Частично» — инструмент готов, но результат зависит от данных или прогонов, которых ещё нет. «Нет» — требует работы людей: сбора текстов, разметки, публикаций.

Главное

Конвейер A–E соответствует ТЗ

Словари-ограничения (модуль B), решение literal/metaphorical по MIP с CoT (модуль C), семантические метки, тональность и домены (модуль D). Вывод содержит все поля ТЗ: Entity, Type, Context_Sentence, Usage_Type, Source/Target_Domain, Semantic_Label, Evidence_Reasoning. Экспорт: ?format=tz.

Методы сравнения готовы

Стратегии zero-shot, few-shot, CoT, RAG и lexicon в любых комбинациях. Провайдеры: OpenAI, Claude, Ollama (Qwen-2.5, LLaMA-3.1) и локальный Transformers с LoRA-адаптером. Декодирование T = 0.2, top-p = 0.95; если провайдер его отвергает, это фиксируется в результате.

Инструменты под H1–H3 и метрики п. 6

IFT-датасет и LoRA-дообучение (H1), фертильность токенизаторов и казахский BPE на 50K (H2), послойный пробинг с MDL (H3). Метрики: F1 по сущностям, бинарной классификации и этикетированию, Fleiss' κ, бутстрэп по произведениям, раннер экспериментов с флагами целей ТЗ.

Блокер — данные

Нет собранных корпусов («Чу Цы», эпос, жырау) и нет Golden Test Set на 300–500 фрагментов от 3 экспертов. Поэтому ни одна цель F1 и ни одна гипотеза ещё не проверены. Словари-ограничения пока стартовые (~50 записей на язык) и требуют проверки филологами.

Пункты ТЗ и состояние

Что осталось, по приоритету

Почти всё оставшееся — работа с данными и людьми. Команды для каждого шага описаны в docs/NLP.md, раздел «Эксперименты по ТЗ».

P0 · данные

Корпуса

  1. Импортировать «Чу Цы» и танскую поэзию: import-chinese-poetry.
  2. Собрать казахские тексты (эпос, жырау, Абай, современные поэты) и импортировать: import-texts.
  3. Проверить лицензии и выставить license_verified.
  4. Очистить корпус: clean --verse-lines.
P0 · люди

Golden Set

  1. Пилот разметки по инструкции v2.0, затем уточнить её.
  2. 300–500 фрагментов, 3 эксперта, слепой первый этап.
  3. Согласие: agreement a b c, цель κ ≥ 0.75.
  4. Филологам расширить словари и базу RAG комментариями Ван И и Чжу Си со ссылками на издание.
P1 · этап 2

Пилотные прогоны

  1. Заполнить experiments/pilot.example.json доступными моделями.
  2. experiment на test: baseline, zero-shot … полный RAG.
  3. Найти идентификатор SozKZ на Hugging Face.
  4. Разобрать ошибки по failures.json и матрицам ошибок.
P2 · этапы 3–4

Гипотезы и публикация

  1. build-ift + finetune на GPU → H1.
  2. fertility, train-tokenizer → H2.
  3. probe на нескольких моделях и seed → H3.
  4. Межкультурный отчёт, публикация датасета и весов, статьи.

Что изменено в этой доработке

  • Таксономия 2.0: типы сущностей, literal/metaphorical, тональность. Старые результаты читаются.
  • Новые модули app/nlp: lexicon, prompts, rag, claude, hf_local, ift, finetune, tokenization, probing, preprocess, importers, experiment.
  • Label Studio v2.0: регионы сущностей, тональность, семантическая метка, подсказки словаря на втором этапе.
  • UI: сущности, тональность, контекст, метод анализа, экспорт в формате ТЗ, новые разрезы на странице сравнения.
  • Документация: RESEARCH.md переписан под H1–H3 и цели п. 6; обновлены NLP.md, контракт и инструкция разметки.

Что стоит знать

  • Современные Claude и reasoning-модели OpenAI не принимают temperature/top-p. Адаптер повторяет запрос без них и помечает это в method.sampling_applied.
  • Цитата Ван И в базе RAG и символические прочтения в словарях — стартовые. Их нужно сверить с изданиями до публикации.
  • Метрики сущностей считаются только на записях gold, где размечены candidates.
  • XLM-R оставлен опорной моделью для сравнения, это не замена LLM.
  • Изменения не закоммичены; копия до слияния сохранена в git stash.
