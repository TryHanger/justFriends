# Инструкция разметки метафор

Версия 2.0 — рабочий протокол команды для китайской и казахской поэзии.
Изменения 2.0 (по ТЗ п. 4.1, 2.2.5): сущности-кандидаты с решением literal/metaphorical,
семантическая метка, тональность, три независимых эксперта и двухэтапная слепая проверка.
До массовой разметки провести пилот с носителями обоих языков и зафиксировать изменения.
Размечать оригинал, сохраняя всю пунктуацию, пробелы и переносы строк.

## Как принять решение

1. Прочитать стихотворение целиком, установить буквальную ситуацию и контекст.
2. Для кандидата записать его значение в данном контексте и более конкретное
   базовое значение. При необходимости сослаться на словарь в журнале разногласий.
3. Проверить, объясняется ли контекстное значение переносом между областями.
   Слово «сердце», огонь, река или луна сами по себе не означают метафору.
4. Выделить минимальное законченное выражение, которое несёт перенос. Для китайского
   не предполагать, что слово обязательно ограничено пробелами; для казахского
   сохранять всю словоформу с аффиксами. Не включать внешнюю пунктуацию и пробелы.
5. Присвоить один тип и по одной исходной/целевой области. Не размечать одну и ту же
   последовательность дважды; пересечения передать на арбитраж.
6. Отметить ключевое слово-образ внутри выражения регионом `entity` с решением
   `metaphorical`, указать семантическую метку и тональность (см. ниже).
7. Отметить регионом `entity` и решением `literal` остальные конкретные и абстрактные
   сущности, которые могли бы нести перенос, но употреблены прямо (растения, животные,
   явления природы, небесные тела, ландшафт, части тела, абстрактные понятия).

Протокол адаптирует идею сопоставления базового и контекстного значений из
[MIPVU](https://www.vismet.org/metcor/documentation/MIPVU.html).
Единица версии 1 — выражение, поэтому это не буквальное воспроизведение лексемной
разметки MIPVU. Решения о границах должны быть единообразными в train и test.

## Типы

- `metaphor`: перенос между областями.
- `personification`: человеческие действия или качества приписаны нечеловеческому;
  выбирать этот тип вместо более общего `metaphor`.
- `simile`: явное образное сравнение, сохраняем как отдельный вспомогательный класс.
  Буквальное сравнение размеров двух камней не является образной фигурой.
- `metonymy`: перенос по смежности (часть/целое, место/люди), а не по сходству.
- `idiom`: устойчивое выражение без отдельно доказанного метафорического переноса.
  Если такой перенос обоснован, выбирать `metaphor` или `personification`.

В основной BIO-задаче положительные типы только `metaphor` и `personification`.
Прочие типы сохраняются для отдельного сравнения и классификации.
Сомнительное место остаётся в `draft`, с объяснением в журнале арбитража.
Не заменять сомнение произвольной уверенностью 0.9.

## Области

| Значение | Определение |
|---|---|
| `nature` | Природа, погода и ландшафт, если нет более точной категории |
| `water` | Река, море, вода, течение |
| `fire` | Огонь, горение, пламя |
| `light` | Свет, сияние, луч |
| `darkness` | Темнота, тень, отсутствие света |
| `plant` | Растения, семена, цветение |
| `animal` | Животные и их действия |
| `body` | Тело, органы, физиология |
| `person` | Человек и специфически человеческие действия; источник олицетворения |
| `object` | Вещь, материал, изделие |
| `space` | Место, вместилище, пространственные отношения |
| `motion` | Движение без самостоятельного образа жизненного пути |
| `journey` | Путь, путешествие, дорога как развёрнутый образ |
| `time` | Время и его течение |
| `life` | Жизнь, существование, судьба |
| `death` | Смерть и прекращение жизни |
| `emotion` | Чувства и переживания, кроме явно выделенной любви |
| `love` | Любовь и привязанность |
| `mind` | Мысль, знание, память, надежда как содержание сознания |
| `society` | Сообщество, власть, отношения людей как социальная система |
| `spirituality` | Духовное или сакральное при явной опоре на текст |
| `other` | Область понятна, но отсутствует в справочнике; описать в журнале |
| `unknown` | Недостаточно контекста, чтобы определить область |

Предпочитать конкретное значение общему: река → `water`, не `nature`.
Смысловая область выбирается по образу и контексту, а не только по ключевому слову.
Не выводить особенности целой культуры из отдельной строки или автоматической метки.

## Сущности, употребление, метка и тональность

| Поле | Как заполнять |
|---|---|
| `entity` (регион) | Слово-образ: 兰, 狐, 月; для казахского — вся словоформа: бөрілер, айдай |
| `entity_type` | `plant`, `animal`, `natural_phenomenon`, `landscape`, `celestial`, `body`, `person`, `artifact`, `abstract`, `other` |
| `usage_type` | `metaphorical` — переносное употребление в этом контексте; `literal` — прямое |
| `semantic_label` | Короткое значение образа в контексте по-русски: «благородный муж» (兰), «хитрость» (狐), «стойкость» (松) |
| `sentiment` | Отношение текста к описываемому: `positive`, `neutral`, `negative` |

Традиционное символическое прочтение из словаря (`data/lexicons/`) — подсказка, а не
решение: орхидея в описании сада остаётся `literal`. Тональность определяется по
отношению к цели переноса, а не по словарной окраске образа. Словарные кандидаты
показываются только на втором этапе проверки (`label-studio-export --prefill-candidates`).

## Учебные примеры

Все примеры ниже искусственные, не цитаты из поэтического корпуса.

| Текст и фрагмент | Решение |
|---|---|
| 我的**心海**泛起波浪。 | `metaphor`, `water → emotion` |
| **Өмір өзені** тоқтамай ағады. | `metaphor`, `water → life` |
| 风在耳边**低语**。 | `personification`, `person → nature` |
| 窗外有一棵树。 | Нет образного переноса по данному контексту |
| 他写下“心海”两个字。 | Упоминание написанного слова не размечается как перенос |

## Пилот и gold

В пилот включить положительные и отрицательные тексты, разные эпохи и авторов.
Golden Test Set (300–500 фрагментов) размечают **три** эксперта.

**Этап 1, слепой.** Каждый эксперт размечает независимо, без подсказок LLM и словаря,
не видя чужой разметки. Считать согласие:
`python -m app.nlp agreement a.jsonl b.jsonl c.jsonl --output runs/agreement.json`
(Fleiss' κ по решениям literal/metaphorical и по символам, Cohen κ и span-F1 попарно).
Цель ТЗ — κ ≥ 0.75. Если ниже, уточнить инструкцию и повторить пилот.

**Этап 2, проверка.** Арбитр разбирает разногласия; эксперты проверяют кандидатов LLM
и словаря на остальном корпусе, не меняя слепой Golden Set задним числом.
Сохранить исходные версии, измерить согласие, затем Арслан разбирает спорные случаи.
Для каждого решения записать ID текста, аннотаторов, спорные границы, решение,
обоснование и версию инструкции. Если меняется правило, пересмотреть прежние примеры.

LLM предлагает предварительную разметку и не принимает решение о статусе gold.
Gold означает полный просмотр текста, включая отсутствие метафор. `spans=[]`
в `unlabeled` и `spans=[]` в `gold` имеют разный смысл.

## Label Studio и Unicode

Импортировать задачи, экспортированные `python -m app.nlp label-studio-export`.
Использовать `label_studio.xml`: выделение `figure` и `source_domain`/`target_domain`
привязаны к одному ID региона. Экспортировать исходный JSON Label Studio.

Импортёр по умолчанию ожидает UTF-16 индексы браузерного выделения и преобразует
их в Python code points. До основной разметки проверить конкретную версию Label Studio
на тексте `🌙心海`: для `心海` UTF-16 диапазон `[2,4)`, Python `[1,3)`.
Если установленная версия экспортирует code points, передать `--offset-unit codepoint`.
Импортёр всегда сверяет `text[start:end]` и не угадывает систему координат.
Не править текст задания между разметкой и экспортом.
